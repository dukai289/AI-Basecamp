# Multimodal Model *多模态模型*

:::tip[内容]
多模态大模型的基本结构、输入表示、训练方式、能力边界和工程化注意事项。
:::

多模态模型（Multimodal Model）指能够处理两种或多种信息模态的模型。这里的模态包括文本、图像、视频、音频等。

在大语言模型语境中，最常见的是视觉语言模型（Vision-Language Model, VLM）：将图像或视频等非文本输入编码为模型可处理的表示，再与文本 token 一起进入语言模型上下文。

需要严格区分两件事：

- LLM 本身仍然在 token 序列上做 next token prediction。
- 多模态模块负责把非文本输入转换为可被 LLM 使用的 embedding、visual tokens 或跨注意力特征。

因此，多模态模型通过编码器、投影层、processor、chat template 和特殊 token，把非文本信息接入语言模型的上下文和生成过程。

一个典型图文 VLM 可以简化为：

```text
图片 / 视频帧
  -> processor
  -> vision encoder
  -> projector / adapter
  -> visual embeddings / visual tokens
  -> LLM
  -> 文本输出
```

---

## 1. 基本概念

### 1.1 多模态模型解决的问题

纯文本 LLM 只能处理已经被表示为文本的信息。

但在现实任务中，大量输入并不是天然文本，很多任务是图像、音视频、文本、上下文和推理共同参与。

多模态模型的目标是让模型在这些输入上完成理解、问答、推理和生成任务。

例如，用户上传报错截图时，模型需要读取错误信息、理解界面状态、结合环境上下文给出排查步骤。

### 1.2 VLM、MLLM 与多模态 Agent

几个概念容易混用：

| 概念 | 含义 | 关注重点 |
| --- | --- | --- |
| VLM (Vision-Language Model) | 主要处理图像 / 视频与文本 | 图文理解、视觉问答、文档和图表 |
| MLLM (ultimodal Large Language Model) | 更宽泛地接入图像、音频、视频等 | 多模态统一表示与跨模态推理 |
| 多模态 Agent | 以多模态模型作为观察能力，并结合工具执行任务 | 看屏幕、听语音、调用工具、执行动作 |

VLM / MLLM 是模型能力层；多模态 Agent 是系统层。

Agent 可能使用 VLM 观察屏幕，再调用浏览器、文件系统、代码执行器或机器人控制接口完成任务。

## 2. 模型结构

### 2.1 Vision Encoder

Vision encoder 是图像侧编码器，常见实现包括 ViT、CLIP vision tower 或专门训练的视觉编码网络。它通常先将图片切成 patch，再编码为视觉特征：

```text
image pixels
  -> image patches
  -> patch embeddings
  -> vision transformer
  -> image features
```

视觉编码器处理的是经过 processor 预处理后的图像，而不一定是用户上传的原始分辨率。resize、crop、padding、动态分辨率切块和归一化参数都会影响模型能否看清小字、细节、空间关系和图表数值。

### 2.2 Projector / Adapter

Vision encoder 输出的视觉特征通常不能直接输入 LLM，因为视觉特征空间和语言模型 hidden state 空间并不一致。Projector 或 adapter 的作用是把视觉特征映射到 LLM 可使用的表示空间。

常见方式包括：

| 方式 | 说明 |
| --- | --- |
| Linear projector | 用线性层将视觉特征映射到 LLM hidden size |
| MLP projector | 用多层感知机做非线性映射 |
| Q-Former / resampler | 用少量查询向量压缩视觉特征 |
| Cross-attention adapter | 在部分层让语言模型读取视觉特征 |

这个模块决定视觉信息如何进入语言模型。Projector 太弱，模型可能只能获得粗粒度视觉语义；视觉 token 过多，则会增加上下文长度、显存和延迟。

### 2.3 Visual Tokens、占位符与 Chat Template

多模态输入通常会在消息中使用图片占位符，例如：

```text
<image>
请解释这张图中的异常。
```

也可能使用结构化消息：

```json
[
  {"type": "image_url", "image_url": {"url": "..."}},
  {"type": "text", "text": "请解释这张图中的异常。"}
]
```

推理框架会将图片交给 processor，把文本消息交给 chat template 和 tokenizer，并将图片占位符与视觉特征对齐。多模态链路可抽象为：

```text
原始图片 / 音频 / 视频
  -> processor
  -> 视觉或音频特征

文本消息
  -> chat template
  -> tokenizer
  -> token ids

特征 + token ids
  -> model
```

这里的 processor、tokenizer、special tokens 和 chat template 都是模型接口的一部分。只迁移语言模型权重，而不迁移视觉模块、processor 或模板，通常无法保留多模态能力。

## 3. 模态类型与典型能力

### 3.1 图像、OCR 与文档理解

图像输入是最常见的多模态形态。能力范围包括物体识别、场景描述、视觉问答、截图理解和文档理解。

OCR 与文档理解尤其重要。它不仅要求识别文字，还要求理解版面结构：

- 标题、正文、脚注和页眉页脚。
- 表格行列、合并单元格和字段值。
- 表单字段、票据编号、印章和签名。
- 截图中的菜单、按钮、错误提示和状态。

VLM 可以同时利用文字内容、版面位置和用户问题，适合截图问答、票据解释和图文混排文档理解。但对财务票据、合同字段、医疗报告等高精度任务，应结合专门 OCR、版面分析、规则校验和人工复核。

### 3.2 图表、表格与空间关系

图表理解要求模型同时识别视觉元素和数值语义：

- 坐标轴、单位、图例和颜色。
- 柱状图、折线图、饼图、散点图。
- 表格单元格、行列标题和合计关系。
- 趋势、异常点、最大值、最小值和比例关系。

常见失败是模型能描述大致趋势，但读错数值、单位或图例颜色。对 BI、财务和科研分析，最好同时提供原始表格数据，或者要求模型输出引用位置与可校验计算过程。

空间关系任务则关注左右、上下、前后、包含、遮挡、数量和相对位置。视觉模型在复杂布局、密集对象、小目标和低分辨率输入中仍可能不稳定。

### 3.3 多图与视频

多图输入常用于对比、排序、排障和变化检测：

```text
图 1 是旧版界面，图 2 是新版界面。请列出变化。
```

多图任务必须明确图片顺序、标签和引用方式。否则模型容易把不同图片内容合并，或只关注其中一张图。

视频模型通常不会逐帧读取完整视频，而是使用抽帧或片段特征：

```text
video
  -> frame sampling
  -> frame encoder
  -> temporal aggregation
  -> LLM
```

视频理解的核心难点是时间信息：事件顺序、动作连续性、片段定位、短暂事件漏检，以及音画是否对齐。低抽帧率会降低成本但可能漏掉关键瞬间；高抽帧率提升覆盖但显著增加延迟、显存和费用。

### 3.4 音频与语音

音频多模态常见两条路线：

| 路线 | 说明 | 优势 |
| --- | --- | --- |
| 级联式 | ASR 将语音转文字，再交给 LLM | 工程成熟，便于检索、审计和纠错 |
| 端到端 | 音频 encoder 直接接入语言模型 | 更容易保留语气、停顿、情绪和实时交互信息 |

语音任务还需要关注识别准确率、多语种、口音、噪声、说话人分离、流式延迟、打断处理和 TTS 稳定性。实时语音 Agent 还必须处理工具调用、长上下文、会话状态和用户中断。

## 4. 训练与对齐

### 4.1 视觉-语言对齐预训练

多模态模型通常不会从零同时训练所有能力，而是在已有视觉模型和语言模型基础上进行跨模态对齐。常见训练阶段是：

```text
视觉-语言对齐预训练
  -> 多模态指令微调
  -> 偏好优化 / 强化学习
  -> 任务专项微调
```

视觉-语言对齐预训练使用图文对、图片标题、网页图文、OCR 文档、视频字幕等数据，让模型学习视觉特征与语言描述之间的对应关系。目标不是让模型学会所有任务，而是让视觉信息能进入 LLM 的表示空间，并被后续生成过程读取。

### 4.2 多模态指令微调

多模态指令微调让模型学会按用户任务使用视觉、音频或视频信息，而不只是描述输入内容。典型数据形式为：

```text
image / video / audio + user instruction -> assistant answer
```

任务可以包括 OCR、VQA、图表问答、多图对比、视频摘要、空间推理、拒答和安全判断。高质量指令数据会决定模型是否能“基于证据完成任务”，而不是生成泛泛描述。

### 4.3 偏好优化与安全对齐

多模态模型同样需要偏好优化或强化学习，尤其是降低视觉幻觉、过度推断和不当识别。

例如，对于模糊图片，可靠回答应该区分：

- 图中能直接观察到的信息。
- 基于上下文可以合理推测的信息。
- 由于分辨率、遮挡或证据不足而无法确认的信息。

偏好数据应鼓励模型在证据不足时表达不确定，而不是补全看起来合理但不可验证的细节。涉及人脸、身份、年龄、健康、隐私和敏感场景时，还需要更严格的安全策略。

## 5. 能力边界与评估

### 5.1 常见失败模式

多模态模型容易给人“已经看懂”的错觉，但它仍然是生成模型，存在明确边界。

| 失败类型 | 典型表现 |
| --- | --- |
| 视觉幻觉 | 说出图中不存在的对象、文字、关系或动作 |
| 小字识别错误 | 截图、票据、表格里的小字或低清文字读错 |
| 空间关系错误 | 左右、上下、包含、遮挡、数量判断错误 |
| 数字不精确 | 图表数值、表格金额、日期和单位识别错误 |
| 过度推断 | 从图片猜测身份、年龄、地点、意图或健康状态 |
| 多图混淆 | 将不同图片的内容合并或引用错图 |
| 视频漏检 | 抽帧未覆盖关键瞬间，导致事件遗漏 |
| 音频误识别 | 噪声、口音、重叠说话导致转写和理解错误 |

生产系统应要求模型区分“可见事实”“上下文推断”和“无法确认”，并对高风险结论加入证据、校验和人工复核。

### 5.2 评估维度

多模态评估需要同时评估输入感知、跨模态推理和语言输出。

| 维度 | 评估重点 |
| --- | --- |
| OCR | 字符准确率、字段准确率、版面和表格结构 |
| VQA | 回答是否基于图像证据，是否答到问题 |
| 图表理解 | 数值、趋势、单位、图例和计算是否正确 |
| 空间关系 | 位置、方向、数量、包含关系和遮挡 |
| 多图对比 | 差异召回率、图片引用是否混淆 |
| 视频理解 | 时序、事件、动作、片段定位和漏检 |
| 音频理解 | ASR、说话人、情绪、延迟和噪声鲁棒性 |
| 安全 | 人脸、隐私、敏感场景、越权推断和拒答 |
| 幻觉 | 是否编造不可见内容或无依据细节 |

评估时必须记录预处理和运行配置：

- 图片原始尺寸、resize、crop、padding 和动态分辨率策略。
- 多图顺序和图片标签。
- 视频抽帧间隔、片段长度和时间戳策略。
- 音频采样率、降噪、分段和说话人分离策略。
- prompt、chat template、processor、tokenizer、模型 revision。

同一个模型在不同 processor 或推理框架下可能表现不同。不记录预处理配置，多模态评估很难复现。

对应阅读：

- [质量与评估](./质量与评估.md)

## 6. 工程化与部署

### 6.1 文件、配置与推理框架

部署多模态模型时，除了普通 LLM 的 tokenizer、权重和 chat template，还要保证视觉或音频侧组件完整。

常见必需文件包括：

- 模型结构配置。
- 语言模型权重。
- vision / audio encoder 权重。
- projector / adapter 权重。
- tokenizer 配置。
- special tokens 配置。
- processor / image processor / audio processor 配置。
- chat template。

推理框架也必须显式支持对应架构与输入类型。需要确认：

- 是否支持该 VLM / MLLM 架构。
- 是否支持图片、视频或音频输入。
- 是否支持动态分辨率、多图和批处理。
- 是否支持流式输出、工具调用和长上下文。
- 是否支持量化后的视觉或音频模块。

有些框架可以启动语言模型部分，但不能正确处理视觉输入。此时系统看似可运行，实际只是在根据文本提示回答。

### 6.2 上下文成本与预处理权衡

图片、视频和音频不会免费进入上下文。它们通常会转成视觉 token、音频 token 或等价 embedding，并占用计算资源。

| 因素 | 影响 |
| --- | --- |
| 输入分辨率 | 分辨率越高，细节保留越多，编码成本越高 |
| 切图策略 | 动态切块能保留小字和局部细节，但增加 token 数 |
| 多图数量 | 多张图通常线性增加视觉上下文和成本 |
| 视频帧数 | 抽帧越密，时序覆盖越好，成本越高 |
| 音频时长 | 长音频增加延迟、上下文和转写成本 |
| OCR 细节 | 小字、表格和截图需要更高分辨率或专用 OCR |

工程上经常需要在“看得清”和“跑得快”之间权衡。低分辨率降低成本但容易丢失小字和细节；高分辨率提升可见信息，但增加延迟、显存和费用。

### 6.3 量化与回归测试

多模态模型量化不只影响语言能力，也可能破坏视觉-语言对齐。常见策略是：

- 语言模型部分量化。
- vision / audio encoder 保持 FP16 或 BF16。
- projector / adapter 保持较高精度。
- 对 OCR、图表、多图、视频和语音任务单独回归测试。

只测试普通文本聊天，无法发现多模态能力退化。多模态回归集应该覆盖真实输入、低清输入、小字、表格、异常样本、长视频和噪声音频。

## 7. 与 RAG、Agent 和业务选型的关系

### 7.1 多模态 RAG

多模态 RAG 可以检索文本、图片、PDF 页面、截图、图表、视频片段或图文混合 chunk。

常见链路是：

```text
用户问题
  -> 检索相关文本 / 图片 / 页面 / 视频片段
  -> VLM 阅读证据
  -> 生成带引用的回答
```

关键问题是证据可追踪。模型回答截图、图表或文档页面内容时，最好能指向原始文件、页码、图片区域或时间戳。否则“有图像输入”并不等于答案可审计。

### 7.2 多模态 Agent

多模态 Agent 可以观察屏幕、理解页面状态、听取语音指令，再调用工具完成任务。例如：

- 看浏览器截图并点击按钮。
- 根据报错截图修改配置。
- 读取仪表盘截图并生成告警。
- 根据机器人视觉输入选择下一步动作。
- 在语音通话中调用订单、日历或客服系统。

这类系统风险更高，因为视觉、音频或页面状态误判可能直接触发错误操作。生产系统需要权限控制、动作确认、回滚机制、操作日志和结果验证。

对应阅读：

- [Agent 智能体](./Agent.md)
- [工具调用](../engineering/工具调用.md)

### 7.3 业务选型原则

选择多模态模型时，不应只看通用榜单。应按任务拆分评估：

| 场景 | 重点关注 |
| --- | --- |
| 截图问答 | OCR、小字、UI 元素、中文能力 |
| 文档抽取 | 表格、字段准确率、结构化输出和校验 |
| 图表分析 | 数字精度、单位、图例、趋势和计算过程 |
| 多图对比 | 图片顺序、差异召回率、引用稳定性 |
| 视频摘要 | 抽帧策略、时序理解、长视频成本 |
| 语音助手 | ASR、TTS、流式延迟、打断和工具调用 |
| 机器人 | 视觉定位、动作规划、安全边界和环境反馈 |

高精度或高风险场景通常不应让 VLM 独立承担全部识别和决策。更稳妥的组合式架构是：

```text
专用 OCR / 检测 / ASR / 解析器
  -> 结构化结果
  -> LLM / VLM 综合推理
  -> 规则校验 / 工具验证 / 人工复核
```

### 7.4 总结

多模态模型的核心是将图像、视频、音频等非文本信息接入语言模型上下文。它通常由 encoder、projector / adapter、processor、chat template 和 LLM 共同组成。

理解多模态模型时，可以抓住几条主线：

- LLM 的生成机制仍然是 next token prediction。
- 非文本输入需要先被编码为视觉、音频或视频特征。
- Processor、tokenizer、special tokens 和 chat template 是模型接口的一部分。
- OCR、图表、多图、视频和语音各有独立的预处理和评估问题。
- 多模态模型仍会幻觉，高风险任务必须加入引用、校验和人工复核。
- 多模态 Agent 是系统层能力，需要工具权限、状态管理和结果验证。

多模态模型把“看见、听见的内容”转成 LLM 可处理的上下文，但可靠上线仍依赖评估集、预处理策略、工程兜底和业务边界设计。
